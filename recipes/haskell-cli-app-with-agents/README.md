# haskell-cli-app-with-agents

Version: `0.1.0`.

Extend [haskell-cli-app-repo](mori://shinzui/seihou-modules/templates/haskell-cli-app-repo)
with the local `agent-gitignore` module. The base keeps its two-package Haskell CLI
scaffold, Nix integration and `git-init` composition. The child adds ignore rules
for `.claude/`, `.codex/`, `.agents/` and `CLAUDE.local.md`, and uses
`moduleOverrides` to preset `git.githubOwner=shinzui` without executing `git-init`
twice. An explicit CLI value can override that preset. No generation module is
copied into this recipe.

Use [Seihou](mori://shinzui/seihou) 0.14.0.0 or newer before adopting this recipe.
From a fresh project directory:

```sh
seihou install https://github.com/shinzui/agent-seihou.git --module haskell-cli-app-with-agents
seihou run haskell-cli-app-with-agents
```

Install follows the explicit base source
`https://github.com/shinzui/seihou-modules.git` and accepts base versions from
`0.1.0` inclusive to `0.2.0` exclusive at default-branch HEAD. It does not search
historical tags. The full closure includes the child, base, `haskell-cli-app`,
`nix-haskell-flake`, `git-init` and `agent-gitignore`. Run is offline after install.
It asks for normal project inputs and shows one combined preview. Publishing a
compatible base version or correcting the producer requirement is necessary when
the interval fails; a consumer downgrade override cannot bypass it.

Preview existing applications with `seihou update haskell-cli-app-with-agents --dry-run`
and accept through `seihou update haskell-cli-app-with-agents`. The normal command
acquires new base/member sources, reuses accepted inputs and optional omissions,
and restores missing caches in fresh clones with a committed manifest. A base-only
change appears even when child version and generated bytes agree; unchanged
application commands stay skipped. Run `seihou upgrade haskell-cli-app-with-agents`
only for intentional cache maintenance; it recommends the project update afterward.

`recipe.dhall` is authoritative. Global binding names retain nearest-child literal
precedence; defaults remain fallbacks. This child does not replace inherited prompt
contracts or declarations. A settings-only specialization can keep its added
`modules` empty and use inherited overrides. Use `seihou help recipes` for the
complete merge and provenance rules.
